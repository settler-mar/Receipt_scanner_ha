# Receipt Scanner

Після запуску натисніть **Відкрити веб-інтерфейс** або відкрийте пункт
**Receipt Scanner** у бічній панелі Home Assistant.

Дані, база SQLite, фотографії чеків, гарантійні PDF та браузерні профілі
зберігаються в постійному каталозі add-on `/data` (в контейнері він підключений
як `/app/data`) і входять у резервну копію add-on.

Для звичайного використання мережевий порт відкривати не потрібно — UI працює
через Home Assistant Ingress. Порт 8001 можна опціонально увімкнути в розділі
Network add-on, якщо потрібен прямий LAN-доступ або OAuth callback магазину.

## Параметри

- `base_url` — залиште порожнім для Ingress. Для OAuth-магазинів увімкніть порт
  8001 і вкажіть адресу, доступну з браузера, наприклад
  `http://192.168.1.50:8001`.
- `secret_key` — ключ шифрування збережених токенів. Задайте його до першої
  авторизації та надалі не змінюйте, інакше старі credentials неможливо буде
  розшифрувати.

- `google_client_id` / `google_client_secret` — OAuth-клієнт Google для інбоксу
  документів (Google Drive). Необов'язкові: без них особисті документи просто
  зберігаються локально в `/app/data/inbox/`. Як створити — див. нижче.

Авторизація Dnipro-M запускає звичайний Chromium у віртуальному дисплеї Xvfb:
фізичного вікна немає, але invisible reCAPTCHA бачить headed-браузер.

## Google Drive для інбоксу документів (крок 3)

Широкі фото (договори, паспорти, бланки) не йдуть у розпізнавання чеків і не
потрапляють у зовнішню AI-модель — вони складаються в чергу «Необроблені».
Якщо під'єднати Google Drive, кожен такий файл одразу заливається у вибрану
папку на вашому Диску; без Drive — лежить локально в `/app/data/inbox/`.

### 1. Створити OAuth-клієнт у Google Cloud

1. Відкрийте <https://console.cloud.google.com/> → створіть проєкт (будь-яка назва).
2. **APIs & Services → Library** → увімкніть **Google Drive API**.
3. **APIs & Services → OAuth consent screen**:
   - тип **External**, заповніть назву застосунку й свій email;
   - на кроці **Test users** додайте свій Google-акаунт (застосунок можна не
     публікувати — режиму «Testing» достатньо для особистого використання);
   - scope додавати вручну не обов'язково — застосунок запитає `.../auth/drive`
     під час підключення.
4. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - тип **Web application**;
   - **Authorized redirect URIs** → додайте точну адресу, яку показує сторінка
     «Налаштування → Google Drive» у застосунку. Зазвичай це
     `http://<ip>:8001/api/inbox/drive/callback` (при роботі через Home Assistant
     Ingress вкажіть `base_url` і ввімкніть порт 8001 — так само, як для
     OAuth-магазинів).
5. Скопіюйте **Client ID** і **Client secret**.

### 2. Додати креденшели в проєкт

Найпростіше — **на сторінці «Налаштування → Google Drive»**: поля **Client ID** і
**Client secret**, кнопка «Зберегти креденшели». Значення зберігається в базі,
secret — зашифрованим.

Альтернатива (задається один раз при розгортанні, має нижчий пріоритет за
введене в UI):
- **Home Assistant add-on:** поля `google_client_id` / `google_client_secret` в
  опціях add-on;
- **Docker Compose / локально:** у `backend/.env`:
  ```
  RS_GOOGLE_CLIENT_ID=<client id>.apps.googleusercontent.com
  RS_GOOGLE_CLIENT_SECRET=<client secret>
  ```

Секрет ніде не логується і назад через API не віддається; refresh-токен
користувача теж зберігається зашифрованим (той самий `secret_key`, що й для
токенів магазинів).

### 3. Під'єднати Drive

**Налаштування → Google Drive → «Підключити Google Drive»** → у вікні згоди
Google оберіть акаунт і підтвердьте доступ → поверніться й натисніть
«оновити». Далі в оглядачі папок оберіть:
- **кореневу папку** — база для всіх документів (звідси починається огляд, тут
  створюються нові папки; необов'язково — за замовчуванням уся ваша Drive);
- **папку «Необроблені»** — куди падають свіжі завантаження до обробки (якщо не
  задана — беремо кореневу). Нову папку можна створити прямо в оглядачі.

Кожній папці в оглядачі можна задати **колір** (кнопка «Колір») — він
застосовується і в застосунку, і в самій Google Drive.

«Відключити» відкликає токен у Google і очищає його з бази.

## MCP-сервер

Застосунок віддає свої дані зовнішньому AI (Claude Desktop тощо) по Model
Context Protocol на `http://<host>:8001/mcp` (Streamable HTTP, без авторизації —
тільки LAN, увімкніть порт 8001). Інструменти:
- читання: `search_products`, `spending_summary`, `list_receipts`, `suggest_store`;
- запис: `add_to_shopping_list` (позиція в список покупок), `add_receipt`
  (записати покупку/чек у базу), `add_fuel_purchase` (заправка — прив'язується
  до вашого акаунта на цій АЗС; можна вказати лише суму або лише літри, друге
  порахується за останньою відомою ціною пального на станції).

Керування — **Налаштування → MCP-сервер**: увімкнути/вимкнути сервер і
**чекбокс на кожен інструмент** — позначені доступні зовнішньому клієнту.
Інструменти, що змінюють дані (`add_to_shopping_list`, `add_receipt`,
`add_fuel_purchase`), позначені окремо і за замовчуванням вимкнені — клієнт їх
не бачить, доки ви не поставите галочку.

Приклади фраз для клієнта (наприклад, Claude Desktop):
- «заїхав на барс і заправився газом на 1639,53 грн» →
  `add_fuel_purchase(store="барс", fuel="газ", amount=1639.53)`
- «заправився на барсі газом 40 літрів» →
  `add_fuel_purchase(store="барс", fuel="газ", liters=40)`
