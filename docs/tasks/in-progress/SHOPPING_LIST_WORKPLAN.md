# Рабочий план: список покупок

Последнее обновление: 15.09.2026

Документ является текущей точкой синхронизации по функциональности списка
покупок. Все новые изменения по этой теме сначала сверяем с ним.

## Цели

- Один общий список покупок для двух пользователей.
- Два равноправных входа: веб и Telegram.
- Чеклист — это временный план конкретного похода, а не отдельный список.
- Список покупок не очищается после завершения чеклиста.
- Фактическое закрытие покупки происходит по чеку.
- Ручная работа нужна только для неоднозначных случаев.

## Что уже сделано

### Общий список

- Добавление одной или нескольких позиций.
- Количество, единица измерения и примечание.
- Дата добавления.
- Метод добавления и автор: веб, Telegram, MCP и т. п.
- Защита от дублей: повторное добавление одинаковой позиции переиспользует
  существующую строку.
- Существующие дубли очищены.
- Явное назначение магазина для позиции.
- Категория позиции.
- Тег позиции.
- Операции над группой выбранных строк выполняются одной общей панелью
  (одинаковой для блоков «До покупки» и «Куплено»):
  - отметить купленными или вернуть в список;
  - назначить или снять магазин (пункт «снять» внутри того же списка);
  - назначить или снять категорию;
  - проставить или снять тег (пустое поле = снять);
  - удалить позиции с подтверждением.

### Магазин

- Магазин можно явно указать в свободной фразе:
  `нужно купить в метро памперсы, сыр`.
- Явно указанный магазин распространяется на все позиции фразы.
- Если магазин не указан, используется общий подбор по истории чеков.
- Для чеклиста можно выбрать магазин отдельно.
- В выбор не включаются магазины без подходящих товаров.
- Показывается количество позиций для магазина.
- Классы магазинов вынесены в backend (`app/services/store_classes.py`,
  `GET /api/stores/classes`): один справочник кодов и подписей, плюс
  соответствие «верхняя категория товара → класс магазина». `/api/stores`
  отдаёт класс каждой сети, позиция списка — свой класс (явно выбранная сеть,
  иначе по категории товара).
- Основная группировка интеграций использует пользовательские классы:
  - АЗС;
  - Строймагазины;
  - Магазины техники;
  - Магазины для дома;
  - Зоомагазины;
  - Магазины одежды;
  - Маркетплейсы.
- В интерфейсе сохранены дополнительные классы для уже существующих типов:
  продуктовые магазины, аптеки и ручное добавление.

### Категоризация и рекомендации

- Категория показывается русским названием, а не системным кодом.
- Категория берётся из словарей, истории чеков и известных правил, а если
  совпадений нет — из AI-классификатора (тот же двухпроходный разбор, что и
  для чеков); ответы кэшируются в `product_category`, поэтому следующая такая
  же фраза раскладывается бесплатно.
- Новая позиция, добавленная в вебе, догоняется AI-классификацией в фоне,
  сразу после ответа сервера.
- Плюс к этому планировщик сам классифицирует список, когда тот «затих»:
  пауза считается от последнего добавленного товара, поэтому серия добавлений
  обрабатывается один раз. Включение и длина паузы (по умолчанию 10 минут) —
  «Налаштування → Список покупок»; каждый запуск пишется в общий журнал
  (страница «Журнал», источник «Список покупок»).
- Есть отдельная кнопка запуска классификации позиций без категории; она
  показывает, сколько разложено по словарям и сколько через AI, и сообщает,
  если AI недоступен.
- Категория показывается как «верхняя категория · подкатегория».
- Учитывается только верхний уровень категории при определении подходящих
  магазинов.
- Для аптек предусмотрен верхний класс «Здоровье и аптека», лекарственные
  товары попадают в подкатегорию «Ліки».
- Рекомендации строятся по обобщённым товарным группам, а не по полному
  названию конкретного бренда или упаковки.
- Защищены важные различия: куриные яйца, декоративные яйца и шоколадные яйца
  не объединяются.
- Для регулярных товаров доступны действия: добавить, отложить и не напоминать.

### Чеки и переходы состояний

- Сильное совпадение с чеком закрывает позицию автоматически.
- Неоднозначное совпадение попадает в блок проверки.
- До подтверждения неоднозначное совпадение не попадает в архив.
- При ручном переносе в «Куплено» сохраняется время переноса.
- Ручная покупка без чека остаётся в блоке «Куплено».
- Позднее появившийся чек может сопоставиться с ручной покупкой без чека.
- После сопоставления дата заменяется датой покупки из чека.
- Архив содержит только подтверждённые позиции, привязанные к чеку.
- Архив группируется по чекам.

### Веб

- Есть три вкладки: покупки, рекомендации и архив.
- Список «До покупки» группируется по типу магазина (по умолчанию), по
  конкретному магазину, по категории или без группировки; внутри группы —
  сортировка: сначала новые, сначала старые, по названию. Оба выбора
  запоминаются в браузере.
- Строка списка компактная: название, количество, категория, магазин, тег и
  примечание — обычным текстом; поле превращается в редактор по клику
  (Enter — сохранить, Esc — отменить).
- Действия не перерисовывают страницу: экран загрузки показывается только при
  первом открытии, дальше список обновляется на месте.
- В блоках «До покупки» и «Куплено» чекбоксы работают как выбор строк.
- Изменение состояния выполняется отдельной групповой кнопкой.
- Для купленной позиции отображаются магазин, дата и чек/ссылка на чек.
- В подключениях есть поиск и фильтр по классу.
- Интеграции сгруппированы по пользовательским классам и помечены бейджами.

### Telegram

- Команды доступны через подсказку Telegram.
- `/shopping` и `/list` показывают список с магазином, категорией и тегом,
  если они указаны.
- `/trip` предлагает только подходящие магазины и показывает выбранный магазин
  и количество позиций.
- Свободные фразы добавления в список поддерживают явное указание магазина.
- В ответе на добавление общие магазин, категория и тег выводятся один раз,
  а не повторяются возле каждой строки.
- Для позиций выводятся индикаторы:
  - `🆕` — новая;
  - `✏️` — существующая изменена;
  - `↩️` — уже была в списке.
- Повторная отправка команды не создаёт дубли.

### MCP

MCP синхронизирован с вебом и Telegram.

Доступны инструменты:

- `add_to_shopping_list` — добавление с магазином, категорией и тегом;
- `list_shopping_items` — просмотр списка с метаданными;
- `update_shopping_item` — изменение одной позиции;
- `bulk_update_shopping_items` — массовое изменение;
- `categorize_shopping_list` — запуск категоризации;
- `shopping_archive` — архив по чекам;
- `create_shopping_trip` — создание чеклиста.

Записывающие MCP-инструменты нужно отдельно разрешить в настройках уровнем
`write`.

## Правила, которые нельзя нарушать

- Не удалять позиции из постоянного списка при завершении чеклиста.
- Не считать ручную отметку доказательством покупки по чеку.
- Не помещать неподтверждённые совпадения в архив.
- Не объединять товары только из-за похожего полного названия без учёта
  категории.
- Не заменять явно указанный пользователем магазин автоматической рекомендацией.
- Не показывать пользователю внутренние коды категорий.
- Не создавать дубли при повторной команде, повторной доставке сообщения или
  повторном запуске процесса.
